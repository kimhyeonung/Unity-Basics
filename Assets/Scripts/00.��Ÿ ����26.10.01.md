### 3. 유니티 스크립트 라이프 사이클 개요

스크립트 라이프사이클 개요 : https://docs.unity3d.com/kr/2019.4/Manual/ExecutionOrder.html

Awake : 스크립트가 실행될 때 한번만 호출됩니다. 모든 오브젝트가 초기화 된 후 호출되기 때문에
GameObject.Find 같은 명령문을 안전하게 사용할 수 있습니다.
Awake 함수는 언제나 Start 함수 전에 호출되므로 초기화 순서를 정할 수 있게 합니다.

OnEnable : 인스펙터뷰에서 체크를 통해서 게임 오브젝트를 활성화 할 때 사용됩니다.
활성화 할 때마다 호출 됩니다.
Start : Update 함수가 호출되기 전에 한번만 호출됩니다.
다른 스크립트의 모든 Awake가 모두 실행된 이후에 실행됩니다.
스크립트가 활성화 되어 있어야합니다.

FixedUpdate : 주로 물리 엔진을 사용하는 경우 일정 시간 간격으로 힘을 가할 때 사용하는 함수입니다.
발생 주기가 일정합니다. (Default : 0.02초)

Update : 프레임마다 호출되는 함수로 게임의 핵심 로직에 사용됩니다. 스크립트가 활성화 되있어야 사용 가능하고,
주기가 일정하지 않습니다.

LateUpdate : 모든 Update 함수가 실행되고 나서 호출됩니다. 주로 카메라 이동 로직에 사용합니다.

OnDisable : 게임 오브젝트 또는 스크립트가 비 활성화 되었을 때 호출됩니다. (Coroutine 사용 불가)

OnDestroy : 오브젝트 생존기간의 마지막 프레임이 업데이트 된 후 실행됩니다. (Object.Destroy 또는 씬 종료 시)

OnApplicationQuit : 응용프로그램 종료 전에 모든 오브젝트에서 호출됩니다. 에디터에서는 플레이 모드를 중지하면 나타납니다.



### 4. Fixed Update / Update / LateUpdate 차이

유니티(Unity)에서 Update는 매 프레임마다 불규칙하게 호출되어 일반적인 게임 로직과 입력을 처리하는 반면,
FixedUpdate는 일정한 시간 간격(기본 0.02초)으로 호출되어 물리 연산에 사용됩니다.
주요 차이점 비교:

구분          Update                               FixedUpdate
호출 주기    매 프레임마다 호출                       고정된 시간 간격마다 호출
(프레임 레이트에 따라 간격이 변동됨)       (기본값: 1초에 50회, 0.02초)
주요 용도     키보드/마우스 입력, UI 처리,           Rigidbody를 이용한 물리 충돌 및 이동 연산
일반적인 객체 이동

deltaTime     프레임 간의 실제 시간이 반환되므로      고정된 간격(Time.fixedDeltaTime)이 반환되므로
곱해서 사용                            곱할 필요 없음

물리 효과(Rigidbody 등)가 적용된 객체를 제어할 때 Update를 사용하면
컴퓨터 사양(프레임)에 따라 이동 속도가 달라지거나
충돌이 뚫리는 버그가 발생할 수 있습니다.

따라서 관련 로직은 반드시 FixedUpdate에서 처리해야 정확한 시뮬레이션을 보장할 수 있습니다.

LateUpdate
- 모든 Update 함수가 호출된 후, 마지막으로 호출됨.
- 주로 오브젝트를 따라가게하는 카메라를 사용할 때 사용

### 11. 직렬화
프로그래밍에서 직렬화(Serialization)란 메모리에 흩어져 있는 복잡한 데이터 구조나 객체를 파일에 저장하거나 네트워크로 전송하기 쉬운 연속적인 형태(바이트나 문자열)로 변환하는 과정입니다.
주요 사용 목적과 개념은 다음과 같습니다.
(1) 왜 사용하나요?: 메모리에 있는 데이터(객체)는 프로그램이 종료되면 사라집니다.
이를 하드디스크에 저장하거나 다른 컴퓨터로 보내기 위해 '일렬로 길게 늘어선 데이터 조각'으로 포맷을 바꾸는 것입니다.

(2) 주요 형식: 대표적으로 JSON, XML, 프로토콜 버퍼(Protocol Buffers) 등의 포맷이 사용됩니다.

(3) 역직렬화(Deserialization): 반대로 직렬화된 데이터를 읽어와 다시 원래의 객체나 데이터 구조로 복원하는 과정을 의미합니다.


개발 언어로 무엇을 사용하던(C++, C, C#, Java 등,,) 사용하는 데이터들의 메모리 구조는 크게 2가지로 나뉜다.

1. 값 형식 데이터(Value Type) : 우리가 흔히 선언해서 사용하는 int, float, char 등, 값 형식 데이터들은 스택에 메모리가 쌓이고 직접 접근이 가능하다.

2. 참조 형식 데이터(Reference Type) : C#에서 Object 타입 혹은 C++에서 포인터 변수들이 여기에 해당된다. 해당 형식의 변수를 선언하면 힙에 메모리가 할당되고 스택에서는 이 힙 메모리를 참조하는(힙에 메모리 번지 주소를 가지고 있음) 구조로 되어있다.

이 두가지 데이터 중에서 디스크에 저장하거나 통신에는 값 형식 데이터(Value Type)만 가능하다.

참조 형식 데이터(Reference Type)는 실제 데이터 값이 아닌 힙에 할당되어있는 메모리 번지 주소를 가지고 있기 때문에 저장, 통신에 사용할 수 없다.


왜 참조 형식 데이터는 사용할 수 없을까 ?

예를 들자면

포인터 변수 Class A 를 선언하고 객체를 만들어 그 주소 값이 0x00045523라고 가정하자.

그리고 이 값을 파일에 포함하여 저장했다고 해보자.

그 후 프로그램을 종료하고 다시 실행해서 주소값 0x00045523을 가져오더라도 기존 A 객체의 데이터를 가져올 수 없다.(프로그램이 종료되면 기존에 할당되었던 메모리(0x00045523)는 해제되고 없어진다)


네트워크 통신 또한 마찬가지이다.

각 PC마다 사용하고있는 메모리 공간 주소는 전혀 다르다.

그렇기 때문에 내가 다른 PC로 전송한 A객체 데이터(0x00045523)은 무의미하다.

이 데이터를 받은 PC에서의 메모리 주소 0x00045523에는 전혀 다른 값이 존재하기 때문이다.

직렬화를 하게 되면 각 주소값이 가지는 데이터들을 전부 끌어모아서 값 형식(Value Type)데이터로 변환해준다.

한 가지 예시를 더 말하자면,

String이 포인터로 구현되어있는 경우 int, double 등 과는 다르게 내부적으로 메모리가 연속적으로 되어있지 않다.(int*는 4byte씩 double* 8byte씩 메모리가 연속적으로 배치되어있음) 이 스트링 데이터를 무사히 저장 혹은 전송하기 위해서는 이 메모리 데이터들을 연속적으로 배치, 값 타입 변조 즉 직렬화를 해줘야 하는 것이다.

### 13. transform.Position Vs rigidbody.position

transform.position 은 위치 변환 -> 위치 계산 -> 물리현상 계산 의 과정을 거치지만
rigidbody.position 은 물리 계산  -> 위치 변환 으로 계산 과정이 한 단계 줄어들기 때문에
rigidbody.position이 transform.position 보다 성능이 좋습니다.
(다만 rigidbody 를 사용하지 않을 때, 즉 강체가 아닐 때에는 rigidbody 가 없기 때문에 transform.position 을 사용합니다.)

규칙 1.
그냥 위치만 바꾸는 오브젝트는 transform.position을 써도 된다.

규칙 2.
Rigidbody2D가 붙어 있고 충돌/물리와 관계있는 오브젝트는
Rigidbody2D.MovePosition, linearVelocity, AddForce 중 하나로 움직인다.

규칙 3.
Rigidbody2D로 움직일 오브젝트의 현재 위치는
되도록 Rigidbody2D.position에서 읽는다.

규칙 4.
다른 오브젝트의 위치를 읽는 것은 transform.position으로 시작해도 괜찮다.

규칙 5.
한 오브젝트 안에서 transform.position 직접 이동과 Rigidbody2D 물리 이동을 섞지 않는다.


### 14. Coroutine

코루틴을 사용하면 작업을 다수의 프레임에 분산할 수 있습니다.

Unity에서 코루틴은 실행을 일시 정지하고 제어를 Unity에 반환하지만 중단한 부분에서 다음 프레임을 계속할 수 있는 메서드입니다.

대부분의 경우 메서드를 호출하면 실행을 완료한 뒤 호출한 메서드에 제어와 선택적 반환 값을 반환합니다. 즉 메서드 내에서 발생한 모든 행동은 단일 프레임 업데이트 내에서 발생해야 합니다.

시간의 흐름에 따른 이벤트의 시퀀스나 절차상의 애니메이션을 포함하기 위해 메서드 콜을 사용하고자 하는 상황에서 코루틴을 사용할 수 있습니다.

하지만 코루틴은 스레드가 아니라는 점을 명심해야 합니다. 코루틴의 동기 작업은 여전히 메인 스레드에서 실행됩니다. 메인 스레드에 소요되는 CPU 시간을 줄이려면 다른 스크립트 코드에서와 마찬가지로 코루틴의 작업 차단을 방지하는 것이 중요합니다. Unity 내에서 다중 스레드 코드를 사용하려면 C# 잡 시스템을 고려하십시오.

코루틴은 HTTP 전송, 에셋 로드, 파일 I/O 완료 등을 기다리는 것과 같이 긴 비동기 작업을 처리해야 하는 경우 코루틴을 사용하는 것이 가장 좋습니다.

###15. Event Action

참고 : https://tears2am.tistory.com/56
참고 : https://docs.unity.com/ko-kr/engine/6000.5/script-reference/unityengine/events/unityaction


(1) Action (시스템 액션) 이란?

• 정의: 반환값이 없는(void) 메서드를 참조할 수 있는 C#의 기본 델리게이트(Delegate)입니다.
• 사용법: using System; 네임스페이스를 선언한 후 사용합니다.
• 특징:
• +=로 메서드를 구독(등록)하고, -=로 구독을 해제합니다.
• 매개변수가 필요할 때는 제네릭을 이용해 Action<int>, Action<string, float> 형태로 확장할 수 있습니다.
• 누구나 직접 변수에 접근해 메서드를 초기화(= null)하거나 외부에서 임의로 실행(Invoke)


(2) event 키워드 (이벤트)의 역할

• 정의: 델리게이트나 Action 변수 앞에 event 키워드를 붙여서 외부 클래스에서의 남용을 방지하는 안전장치입니다.
• 특징:
• event Action으로 선언하면, 선언된 클래스 내부에서만 해당벤트를 호출(Invoke)하거나 초기화할 수 있습니다.
• 외부 클래스에서는 오직 구독(+=)과 구독 해제(-=)만 가능하므로, 다른 코드가 실수로 이벤트를 강제로 발동시키거나 리셋하는 버그를 막아줍니다.

(3)  Action vs event Action 핵심 비교

구분	일반 Action	event Action (추천 방식)
선언 방식	public Action OnPlayerDead;	public event Action OnPlayerDead;
외부 호출(Invoke)	외부에서 가능 (안전성 낮음)	불가능 (선언한 클래스 내부만 가능)
외부 초기화 (= null)	외부에서 가능	불가능
구독 및 해제 (+=, -=)	외부/내부 모두 가능	외부/내부 모두 가능
인스펙터 노출	노출되지 않음	노출되지 않음

(4) 주의!
이벤트를 구독한 상태로 오브젝트가 비활성화되거나 다시 활성화되면 메소드가 중복 등록될 수 있음
따라서 OnEnable에서 구독했다면, OnDisable에서 반드시 해제해야함.

(5) 예시
using System;
using UnityEngine;

public class PlayerController : MonoBehaviour
{
// 1. event 키워드를 사용해 외부에서 함부로 Invoke하지 못하도록 보호
public event Action<int> OnHpChanged;

    private int hp = 100;

    public void TakeDamage(int damage)
    {
        hp -= damage;

        // 2. 이벤트를 발생시키는 것은 오직 이 클래스 내부에서만 가능
        OnHpChanged?.Invoke(hp);
    }
}

public class UIManager : MonoBehaviour
{
[SerializeField] private PlayerController playerController;

    private void OnEnable()
    {
        // 3. 외부에서는 구독(+=)만 가능
        playerController.OnHpChanged += UpdateHpUI;
    }

    private void OnDisable()
    {
        // 4. 오브젝트가 비활성화/파괴될 때는 반드시 구독 해제(-=)
        playerController.OnHpChanged -= UpdateHpUI;
    }

    private void UpdateHpUI(int currentHp)
    {
        Debug.Log($"UI 갱신: 현재 체력 {currentHp}");
    }
}
